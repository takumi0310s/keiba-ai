### 1-2. tyb merge bug (V15 cache 観察)

```
df shape: 527,280 × 232
constant-value columns (merged but defaults only):
  jrdb_paddock_idx        : 全 50.0 (unique=1)
  jrdb_odds_idx           : 全 50.0 (unique=1)
  jrdb_body_code          : 全 4 (unique=1)
  jrdb_demeanor_code      : 全 2 (unique=1)
  jrdb_live_composite_idx : 全 50.0 (unique=1)
```

→ V15 cache 構築時に tyb merge が機能していなかった (race_id format 不一致疑い)。 これらは V15 features 145 に **含まれていない** (= 学習に害なし) が、 v15.2 では正しく merge する。

### 1-3. race_id 形式

```
tyb: 201506010101 (JRDB 12-digit YYYYJJKKDDRR)
  = 2015 (year) + 06 (場コード) + 01 (回) + 01 (日) + 01 (R)
V15 cache: '0915150804' (TARGET 10-digit、 別フォーマット)
```

merge には JRDB 12-digit → TARGET 10-digit 変換 or 両方 dataframe に共通 key 列構築が必要。 既存 jrdb_features.py の merge logic (`tools/jrdb_features.py:1154`) は予測時 (1 race) 用、 学習時 (527K rows) 用は **新規 implementation 必要**。

## 5. v15.2 学習 plan

### 5-1. 既存 cache merge logic

```
1. load data/_v15_optuna_df_cache.pkl.gz (V15 cache、 527K rows × 145 features)
2. tyb_for_merge.py 新規実装:
   - jrdb_tyb.csv の race_id (JRDB 12-digit) を TARGET 10-digit に変換
   - or V15 cache に jrdb_race_id 列を追加 (year_full + course_code + kai + nichi + race_num から構築)
   - merge on [race_id_canonical, umaban]
3. cha も同様 (race_id format は tyb と同じ)
4. FE 17 features を順次 compute (groupby race_id で rank/zscore、 horse_id+date 順で trend)
5. v15.2_cache.pkl.gz として 永続化 (V15 cache は 一切 上書きしない)
```

★ V15 cache は **read-only**、 v15.2_cache は別 file ★

### 5-2. WF 6-fold 評価

```
fold 1: train 2015-2019、 val 2020 (Q1 のみ)
fold 2: train 2015-2020、 val 2021
fold 3: train 2015-2021、 val 2022
fold 4: train 2015-2022、 val 2023
fold 5: train 2015-2023、 val 2024
fold 6: train 2015-2024、 val 2025
```

(V15 master と同一条件、 train/train_v15_master.py を base に v15_2_master.py 作成)

### 5-3. 採用判定基準 (絶対)

| 項目 | 基準 |
|------|------|
| WF AUC 平均 | ≥ V15 0.8939 + 0.005 (= **≥ 0.8989**) |
| 全 fold AUC | ≥ 各 fold V15 + 0.003 (全 6 fold 上回り必須) |
| 実 ROI (戦略⑦込み) | ≥ V15 140% + 3pt (= **≥ 143%**) |
| LIVE retro (3 週末) | winner_top1 rate ≥ V15 + 2pt、 shift ≤ 12x |
| LEAK 監査 | 全 17 features individual + 集約で leak audit PASS |
| 採用条件 | 全 5 項目 PASS |

★ 1 項目でも未達 → **採用 NO-GO、 V15 維持** ★ (V15.1 SKB 失敗、 V18/V19 sib hybrid 失敗の教訓)

## 6. fabrication 防止 + honest 留意点

### 6-1. 「想定 +AUC」 = assumption

本 doc の `想定 +AUC` 列は **すべて事前推定 (assumption)**、 実測は学習後判明。
根拠:
- R-1 / R-2 (rank features) は jrdb_tyb_eval_report.md の padock_idx 単独 AUC 0.619 と race-internal な normalization で 中-上位 power 想定
- C-* (cross) は LGB が内部で interaction 捕捉する可能性大 (V20/V22 interaction PoC 失敗 (Session #57): LGB は既に内部で捉えている)
